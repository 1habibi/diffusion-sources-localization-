## Что проверяем

Вместо фиксированного бонуса ранним узлам обучаем небольшую линейную модель
на шести наблюдаемых признаках. GCN, count-head и финальные кандидаты прежние.
Это три CPU fit, а не новое длительное обучение GCN.

[Notebook](../notebooks/colab_temporal_learned_reranker.ipynb): ячейки 1–2 код/пути;
3 smoke без обучения; **STOP перед 4**; 4 cache 2160 train; 5 подтверждение и
fit/select; 6 validation; 7 repeats; 8 summary. Не использовать «Run all».
После failed gate нижние ячейки и прямой CLI не разрешают продолжить оценку.

## Как читать показатели

- **F1** — баланс точности выбранных источников (precision) и полноты найденных
  истинных источников (recall), от 0 до 1; больше лучше. Усредняем по каскадам.
  F1=0.5 не означает «50% полностью правильно решённых каскадов».
- **Precision** — какая доля предсказанных узлов действительно источники.
- **Recall** — какая доля истинных источников найдена.
- **Exact-set accuracy** — доля каскадов, где угадано всё множество источников
  без лишних и пропущенных узлов; больше лучше.
- **Count accuracy / count MAE** — доля правильных оценок количества / средняя
  абсолютная ошибка количества. В этом пилоте число не меняется, поэтому
  улучшения этих показателей не обещаем.
- **Symmetric set distance** — среднее ближайшее расстояние в обе стороны между
  истинными и предсказанными источниками, в рёбрах графа; меньше лучше.
- **Hit@1/2-hop** — доля истинных источников, рядом с которыми есть предсказание
  не дальше одного/двух рёбер; больше лучше, но это не точное нахождение узла.
- **Delta F1** — learned F1 минус F1 текущей v3 на тех же каскадах. +0.02 —
  две процентные точки шкалы F1, не «улучшение на 2%» в относительном смысле.
- **95% paired bootstrap CI** — интервал неопределённости парной разницы F1
  при повторных выборках каскадов с сохранением групп k. Нижняя граница >0
  поддерживает положительный прирост на данном development-наборе.
- **Sample SD по seed** — разброс между тремя frozen GCN; это не CI и не три
  независимых новых набора данных.

Прирост нужен >=0.02 относительно **v3**, не только snapshot. Exact не должен
ухудшиться; групповые провалы ограничены 0.02. Dev без CI, validation с CI;
summary усредняет каждый каскад по seed перед bootstrap. Все результаты
exploratory: исходная GCN видела train, validation ранее использовалась.

## Сохранение и бюджет

Новые артефакты: `reports/runs/temporal_v3_learned_reranker/v1/`.
Cache содержит числовые NPZ; выбранная модель/scaler — JSON внутри защищённой
selection. При смене device/runtime или входов нужен новый output root;
нельзя молча переиспользовать несовместимый кэш. Partial стадии не перезаписываются.
Лимит 1800 s проверяется между операциями, до/после каждого оценочного каскада
и bootstrap, а не принудительным прерыванием solver/одного bootstrap вызова.
Identity также учитывает присутствие/содержимое distance cache и весь локальный
Python-пакет: изменились зависимости — старые стадии не принимаются.
Cache/fit на настоящих данных требуют отдельного согласования после smoke.
Test, final_holdout и independent_holdout этот pipeline не читает.
Пройденный пилот не разрешает автоматически новую независимую проверку или UI deployment.
