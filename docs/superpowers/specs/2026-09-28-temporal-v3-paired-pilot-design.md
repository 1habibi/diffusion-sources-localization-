# Temporal-v3: парный пилот без обучения

Дата: 2026-09-28. Статус: дизайн оформлен после согласования правил в чате; ожидает просмотра пользователем. Реализация не начата.

## Задача и границы

Проверить, улучшает ли дополнительное раннее наблюдение локализацию источников достаточно заметно, чтобы оправдать дальнейшее обучение temporal-модели для диплома. Пользователь не хочет длительных Colab-запусков ради малых изменений метрик и просит точные инструкции по отдельным ячейкам и ведение development log.

Текущий контроль — замороженная S1b: validation F1 по seed 7026/7027/7028 равен 0.358542 ± 0.004843. Top-M диагностика не поддержала узкий shortlist как основной путь улучшения сложных каскадов. Разведка на 200 validation-примерах показала временной сигнал, но не измеряла прирост F1.

Этот этап — отдельный `temporal_v3_paired_pilot`, а не переобучение S1b и не окончательная оценка v3. Он использует только существующие train/validation. Исходные test и final holdout не читаются. Полноценный новый temporal-датасет, neural temporal encoder, обучение и финальная оценка находятся вне текущего этапа и потребуют отдельного дизайна.

## Согласованная постановка наблюдений

- Финальный снимок, граф, признаки S1b и candidate mask берутся из сохранённого snapshot-датасета без изменений.
- Ранний снимок снимается после шага IC `t1=1`; финальный соответствует исходному `max_steps=3`, включая случаи раннего завершения каскада. Снимок t=0 не выдаётся.
- Каждый узел, заражённый к t1, независимо включается в раннее наблюдение с вероятностью, равной сохранённой observation_fraction. Источники не включаются принудительно, отдельного source-флага нет. Пустое раннее наблюдение допустимо; такие случаи не отбрасываются.
- Раннее и финальное наблюдения — две независимые неполные выборки, а не накопительный журнал: ранний узел может отсутствовать в финальном наблюдении. Это явно указывается в отчёте. Финальный протокол сохраняет своё исходное допущение о наличии источников среди кандидатов; оно не объявляется реалистичным для всех приложений.
- Для простого корректора используется только бинарный признак раннего наблюдения у финальных кандидатов. Истинное время заражения и новые узлы за пределами финального candidate set не используются корректором.

Выбран этот вариант вместо накопительных наблюдений: он сохраняет финальный вход и множество кандидатов и позволяет точное парное сравнение. Простое сокращение списка кандидатов по раннему снимку запрещено: истинные источники могут не быть замечены рано.

## Воспроизведение каскадов и защита от утечки

История восстанавливается из config.yaml и сохранённых simulation_seeds. Сначала вызывается SourceSampler с исходными условиями и RNG, затем simulate_ic с тем же уже продвинутым RNG. Вызвать simulate_ic сразу с исходным seed недостаточно: выбор источников ранее потреблял случайные числа.

Для каждого примера обязательно проверяются точные совпадения восстановленных источников, итогового infected mask и финального наблюдения/candidate mask с архивом. Любое несовпадение останавливает пилот, а не пропускает пример. Порядок условий воспроизводится по индексу принятого примера, как в исходном генераторе. Проверяются сохранённые k, probability и observation_fraction.

Ранний RNG отдельный: SeedSequence([5000000, observation_seed, 1]); перебор узлов всегда отсортирован. Этот алгоритм отличается от разведочного throwaway-пилота и фиксируется до оценки F1. Сохраняются его версия, seeds и хеши входов.

Источники и infection_times доступны только восстановлению симуляции и оценщику, не скоринговому интерфейсу. Source-blind sampler получает только множество заражённых к t1, вероятность наблюдения и RNG. Тест проверяет, что изменение меток источников при фиксированных этих входах не меняет раннее наблюдение.

## Проверяемые варианты и настройка

1. Контроль: исходный predict_joint S1b на неизменном финальном снимке.
2. Временная подсказка: для каждого финального кандидата score = sigmoid(source_logit) + beta * early_observed. Выбираются top-k по этому score, где k — тот же прогноз count-head S1b, ограниченный числом кандидатов.

Никакие веса GCN или count-head не меняются. Все кандидаты остаются доступны. При beta=0 результат должен точно совпасть с контролем; для этого используется исходная процедура выбора, а не иной tie-break. При beta>0 равенства разрешаются исходным score, затем индексом узла.

Сетка beta заранее ограничена значениями [0, 0.1, 0.25, 0.5, 1.0]. Выбор только по среднему per-cascade F1 первых 540 train-примеров (10 полных циклов исходных 54 условий). Проверяется фактическая сбалансированность этой выборки. При равном F1 выбирается меньшее beta. Никакого подбора по validation, по отдельному k или по размеру candidate set нет. Beta после выбора сохраняется в manifest.

Первый запуск использует S1b/seed_7026. Контроль на полном validation должен совпасть с сохранённым F1 0.362996329663 с допуском 1e-6; аналогичная проверка выполняется для выбранной train-выборки при наличии сохранённых per-example predictions. Полный train F1 не сравнивается с F1 подвыборки.

## Оценка и решение о следующем этапе

На всех 1998 validation-примерах сравниваются контроль и единственный выбранный beta. Отчёт включает F1, precision/recall, exact-set accuracy, count accuracy, graph distance, Hit@1/2-hop, F1 по k и диапазонам candidate set, долю источников и каскадов, покрытых ранним наблюдением, и долю пустых ранних снимков. Count accuracy должна оставаться неизменной.

Для разницы F1 строится парный bootstrap по каскадам, стратифицированный по истинному k: 2000 повторов, seed 9282026, percentile CI 95%. Одинаковые индексы используются для обеих систем. Разброс по training seed и этот bootstrap описывают разные виды неопределённости.

Первичный gate: delta F1 >= 0.02, нижняя граница CI > 0, снижение F1 ни для k=2, ни для k=3 не больше 0.02. Если gate не пройден — результат сохраняется, дорогое temporal-обучение в этом цикле не запускается. Это бюджетное правило, а не доказательство бесполезности временной информации.

Если gate пройден, повторить только inference для frozen seed 7027 и 7028 с теми же ранними масками и beta, выбранным на train seed 7026. Нового подбора beta нет. Переход к дизайну обучаемой temporal-модели допускается при положительном delta на каждом seed и среднем delta >= 0.02; при неоднозначности — остановка и обсуждение, не автоматический новый sweep.

Validation уже участвовала в разведке: положительный результат остаётся exploratory и не доказывает generalization. Для подтверждения будущей temporal-модели нужен отдельно версионируемый независимый temporal-датасет и закрытая оценка. Рост качества объясняется дополнительной доступной информацией, а не архитектурным превосходством при одинаковом входе.

## Компоненты и артефакты будущей реализации

Разделить восстановление истории, source-blind sampling, коррекцию scores и парный evaluator. Использовать текущие функции загрузки графа/данных, модели, inference и метрик; не менять поведение snapshot-training CLI.

Результаты хранить в новом каталоге reports/runs/temporal_v3_paired_pilot/, отдельно от frozen runs. Сохранить manifest (input/checkpoint/config hashes, code revision, RNG policy, train indices, выбранный beta), per-example predictions, таблицу метрик, CI и gate decision. Исходные архивы, checkpoint, ablation state и freeze manifest не перезаписывать. Повторный запуск с другими входными хешами не должен молча использовать старый кэш или отчёт.

Отдельный Colab notebook предоставляет пронумерованные setup, smoke, train-selection, validation и optional frozen-seed ячейки. Не использовать Run all, не скрывать длительные subprocess-ошибки. Проверять импорт в самом notebook kernel, а не только через pytest; пути и устройство печатать до вычислений. Маски и inference допускается кэшировать с проверкой хешей для повторов; GPU нужен лишь для inference, не для обучения. Время восстановления сначала измеряется на smoke, обещание фиксированной длительности не даётся.

## Проверки перед запуском

- Точный replay на небольшом детерминированном IC-примере и реальном development smoke.
- t1 > 0; пустые ранние снимки и остановившиеся каскады обрабатываются без фильтрации.
- Source-blind sampling воспроизводим и не имеет доступа к source labels.
- Beta=0 даёт идентичный контроль; корректор не удаляет кандидатов и не меняет count prediction.
- Train-selection не загружает validation; validation не меняет beta.
- Пилот не открывает test/holdout, не изменяет старые артефакты.
- Bootstrap парный, воспроизводимый и корректен на синтетических дельтах.
- Saved-control F1 gate останавливает запуск при несовпадении checkpoint/данных/кода.
