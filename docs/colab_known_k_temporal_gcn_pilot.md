# Colab: pilot Temporal-GCN с известным числом источников

Это отдельный исследовательский эксперимент. Модель получает конечный снимок, ранний снимок и **заданное истинное число источников** `k ∈ {1, 2, 3}`. Это не основная постановка «угадать и число, и вершины по одному снимку». Ранний снимок должен реально присутствовать в задаче; он не выводится из конечного снимка. Сравнение с frozen S1b и Temporal-v3 проходит на тех же validation-примерах и с тем же известным `k`.

Ноутбук: [colab_known_k_temporal_gcn_pilot.ipynb](../notebooks/colab_known_k_temporal_gcn_pilot.ipynb). Ветка `experiment/known-k-temporal-gcn` пока локальная: перед Colab её надо опубликовать на GitHub отдельным согласованным действием. До публикации ячейка setup не сможет её клонировать. `master`, старые checkpoint и `thesis_report/` в этом pilot не меняются.

## Что запускать

1. Открой именно этот notebook в Colab, выбери GPU (T4 достаточно для pilot). Ячейка **1 — setup** монтирует Drive, клонирует отдельную ветку в `/content/diffusion-sources-known-k`, ставит отсутствующие зависимости, проверяет путь импортированного кода и печатает Git revision/устройство. Она не запускает обучение. Если ветка ещё не опубликована, остановись здесь.
2. Ячейка **2 — paths** показывает четыре пути. Проверь, что `data_dir` содержит `graph.npz`, `train.npz`, `validation.npz`, `config.yaml`, а в `frozen_s1b_dir` есть `config.yaml` и `best_model.pt`. Новый output: `/content/drive/MyDrive/diffusion-sources/reports/runs/known_k_temporal_gcn_pilot/v1`. Это отдельная папка, не старый `facebook_main_v2`.
3. Ячейка **3 — freeze** фиксирует SHA-256 входов и проверяет совместимость настоящего S1b checkpoint. Если ошибка, остановись и пришли полный traceback. Она не обучает модель.
4. Ячейка **4 — smoke** обучает на CPU лишь 6 train + 6 validation примерах одну эпоху, проверяет механический путь и checkpoint. **Остановись после неё и пришли вывод.** Её F1 не показатель качества новой модели.
5. Только после проверки smoke и согласования долгого запуска ячейка **5 — approve** требует точный ввод `RUN_KNOWN_K_TEMPORAL_PILOT` и наличие GPU. Это ручное подтверждение. Если нажать `Run all`, выполнение остановится на запросе ввода; pilot без фразы не начнётся.
6. Ячейка **6 — pilot** обучает один seed `7026` на train, выбирает checkpoint по validation и считает парные validation-метрики. Она печатает `quality_gate` и путь отчёта. **Остановись и пришли весь вывод; другие seed, independent holdout и UI пока не запускаем.**

При повторном запуске готовой стадии проверяются SHA-256 её артефактов; повреждение входа или результата вызывает ошибку, а не тихую перезапись. Для прерванного долгого pilot предусмотрен отдельный явный `resume=True` после проверки причины прерывания — не добавляй его в notebook самостоятельно.

## Как читать результаты

Все величины ниже усредняются по каскадам; больше — лучше, кроме расстояния. `snapshot` — замороженная S1b по конечному снимку, `control` — Temporal-v3 с фиксированной поправкой `beta=0.5`, `candidate` — новая обученная Temporal-GCN. Во всех трёх вариантах число `k` дано заранее.

| Поле | Простое значение |
| --- | --- |
| `precision` | Какая доля названных моделью вершин действительно является источниками. |
| `recall` | Какая доля настоящих источников найдена. |
| `f1` | Баланс precision и recall; главный показатель pilot. |
| `exact_set_accuracy` | Доля каскадов, где найдено **всё** множество источников без лишних вершин. |
| `symmetric_set_distance` | Среднее графовое расстояние между истинными и выбранными источниками; меньше — лучше. Это не процент точного угадывания. |
| `hit_at_1_hop` / `hit_at_2_hop` | Доля источников, локализованных в пределах одного/двух рёбер графа; это приблизительное попадание, не точное. |
| `delta_f1` | F1 новой модели минус F1 Temporal-v3 на тех же примерах; `+0.02` означает +2 процентных пункта F1. |
| `f1_ci` | Парный bootstrap-интервал для `delta_f1`; нижняя граница > 0 поддерживает положительную разницу на данном validation-наборе. |
| `by_k`, `by_candidates` | Разрезы по истинному числу источников и размеру candidate set; показывают, где модель выигрывает или проигрывает. |
| `count_accuracy` | `null`/N/A: число источников задано на входе, поэтому «100% угадано» здесь было бы некорректно. |

Заранее зафиксированный gate требует `delta_f1 ≥ +0.02`, нижнюю границу парного CI > 0, отсутствие падения exact-set accuracy и отсутствия существенного (больше 0.02 F1) провала в каждом разрезе. `passed=false` — честный отрицательный результат pilot. Даже `passed=true` на validation — только основание планировать отдельное подтверждение, а не заявление о доказанном улучшении на независимом наборе. Test и independent holdout notebook не открывает.
