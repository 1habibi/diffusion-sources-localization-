# Локальная точка возврата Temporal-v3

Техническая инструкция, не чистовик диплома. Дата проверки: 2026-09-29.

## Где лежит сохранённый вариант

Папка относительно корня проекта: `reports/backups/temporal_v3_20260929/`.
Содержимое скачано с личного Google Drive; оригиналы не изменены.
Резервная копия занимает около 58 MB. Контрольные суммы и Drive ID записаны
в `backup_manifest.json` внутри этой папки.

- `runs/s1b/seed_7026/` — основной ранее выбранный запуск S1b.
- `runs/frozen_candidate/seed_7027/`, `seed_7028/` — два повторных запуска.
- В каждой папке запуска: `best_model.pt`, `last_checkpoint.pt`, неизменённый
  `config.yaml`, `metrics.json`, история обучения и validation-предсказания.
- `data/reference/` — исходные train/validation/test, граф и настройки генерации.
- `data/independent/` — уже открытый независимый набор и его настройки.
- `data/snapshot_final_holdout/` — исходный старый holdout, скопированный локально
  и проверенный по хешу, без оценки его целевых метрик.
- `data/raw/facebook_combined.txt.gz` — исходный граф.
- `independent_evaluation/` — исходные freeze/seal/opened, результаты трёх
  запусков и summary, включая предсказания и манифесты.
- `code_ef56aee.zip` — архив Git revision
  `ef56aeefa80bb5b7237bc6bfac69ed76fab1a6a8` с кодом, конфигурациями и notebooks.

## Что значит «восстановить модель»

Temporal-v3 — S1b GCN плюс раннее наблюдение после первого шага IC и поправка
ранжирования с beta=0.5. Отдельного обученного temporal-checkpoint нет.
Число источников выдаёт прежняя GCN; поправка меняет выбор узлов, а не count-head.

Для inference нужны `best_model.pt`, конфигурация модели, правильный порядок
признаков, граф и код обработки наблюдений. Для продолжения обучения дополнительно
нужны `last_checkpoint.pt`, обучающий набор и совместимое окружение.

Исходные конфигурации намеренно оставлены побайтно неизменёнными: в них есть
пути `/content/drive/...` и `device: cuda`. Они не становятся локальными сами.
При локальном запуске передавать пути из `local_paths.json`, CPU device и
явный путь к checkpoint; относительные пути разрешать от папки резервной копии.
Не редактировать оригиналы для нового эксперимента — создавать отдельные настройки.

## Что проверено

1. Размеры 60 файлов с Drive соответствуют метаданным; SHA256 всех файлов
   сохранены в локальном манифесте.
2. SHA256 трёх `best_model.pt` и их конфигураций совпали с frozen identity.
   Исходные train/validation/test совпали с зафиксированными хешами.
3. Независимые данные совпали с seal; файлы всех семи стадий результатов
   совпали со своими манифестами. Summary совпал с копией для графиков диплома.
4. Все 47 Python-исходников совпадают с frozen source hashes после нормализации
   CRLF→LF. В Windows checkout и Git-архиве строки CRLF, в Colab — LF.
   Это не побайтное совпадение исходников. Строгий guarded workflow может
   потребовать исходники с LF; его проверки нельзя отключать ради запуска.
5. Все три модели загрузились на CPU, по 21252 параметра. На первых 12 уже
   открытых независимых примерах каждого seed совпали snapshot/temporal
   множества источников и predicted count с сохранёнными Colab результатами;
   beta=0 возвращает baseline. Полная оценка 1998 примеров не повторялась.
6. Три resume-checkpoint безопасно прочитаны в weights-only режиме с явным
   allowlist стандартных NumPy типов: есть optimizer, RNG, история и состояние
   модели. Последние эпохи: 7026 — 41, 7027 — 15, 7028 — 29.
   Продолжение обучения не запускалось.

Локальное окружение: PyTorch 2.13.0+cpu, NumPy 2.5.3; Colab использовал
PyTorch 2.11.0+cu128 и NumPy 2.1.3. Smoke-проверка подтверждает указанное
совпадение предсказаний, но не гарантирует побайтную идентичность всех вычислений
или идентичную траекторию продолженного обучения между окружениями.

Distance cache не скачан: стандартный builder детерминированно пересчитывал
расстояния в памяти. Старые pilot/early-baseline report trees не включены:
эта папка сохраняет модель, данные и итоговую оценку, но не является автономной
копией всех исторических входов guarded freeze/seal/open pipeline.

## Как не потерять рабочий вариант

Считать эту папку неизменяемой точкой возврата. Для новых запусков выбирать
другую папку и отдельную конфигурацию; не обучать поверх этих checkpoint.
В приложение подключать выбранную модель явным путём, сохраняя возможность
вернуться к этому комплекту. Само приложение ещё использует старый demo-flow;
подключение Temporal-v3 — отдельный следующий этап.

GitHub хранит код, но `.pt`, `data/generated/` и `reports/` исключены из Git.
Обычный push эту резервную копию не отправит. Сейчас комплект есть на Drive
и локальном диске; для дополнительной страховки можно скопировать всю папку
на внешний носитель.

Чистовик диплома остаётся в `thesis_report/`. Эта инструкция, манифесты,
экспериментальные планы и dev-лог не предназначены для вставки в диплом.
Уже открытый независимый набор не использовать для настройки улучшений.
