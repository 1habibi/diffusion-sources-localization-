# Colab: техническая поправка к открытой known-k independent оценке

Notebook: [colab_known_k_independent_amendment.ipynb](../notebooks/colab_known_k_independent_amendment.ipynb), ветка `experiment/known-k-independent-amendment`. Это **не новый закрытый holdout** и не повторное обучение. Набор seed `5007026` уже открыт, отчёт 7026 уже сохранён. Поправка введена **после открытия** из-за обнаруженной численной ничьей во вспомогательной S1b: на одном из 1998 каскадов повторные GPU-вызовы давали разные узлы при разнице логитов порядка `1.19e-7`. Сравнение основных моделей, параметры, `beta=0.5`, статистический gate и сам датасет не меняются.

В исходной версии `seed_7027` вычислил все 1998 примеров, но **не сохранил отчёт**, поскольку проверка требовала побитового совпадения вспомогательных узлов S1b между запусками. В диагностике, присланной пользователем, отличались только `snapshot_estimated_sources` и `snapshot_sources` на индексе 1440; истинные источники, маски, candidate set и known-k контроль совпали на всех 1998. Исходный `seed_7026` остаётся подписанным SHA-артефактом в `.../v1/seed_7026`.

Поправка требует точного совпадения каждой пары каскадов: индекса, истинного `k`, истинного множества, кандидатного множества, обеих масок, **полного known-k контрольного прогноза с метриками**, числа источников по S1b и всех метрик S1b. Допускается расхождение только в двух списках ID узлов — `snapshot_estimated_sources` и `snapshot_sources`. Оно считается и сохраняется в audit; любой иной дрейф останавливает расчёт. Исходные строки каждого seed не переписываются. В сводной описательной таблице S1b используется один канонический проход seed 7026, поскольку модель S1b одна и та же; его выбор не зависит от качества кандидата. Парный bootstrap по 1998 каскадам и три заранее заданных условия успеха выполняются прежним кодом.

## Как честно описывать итог

Сильная сторона остаётся прежней: новые IC-каскады не использовались для обучения, параметры и гиперпараметры заморожены, контроль и GCN сравниваются на одинаковых данных. Но software-поправка сделана **после открытия** и после просмотра результата 7026, поэтому результат нельзя называть полностью неизменённым preregistered confirmatory test. В дипломном отчёте следует указать исходный отказ проверки, численную ничью, единственное изменение правила парности для вспомогательной S1b и сохранение прежнего основного критерия. Отрицательный итог также сохраняется без подбора.
